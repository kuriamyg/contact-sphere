# 0012 — Database access: Prisma 7, two roles, guarantees in SQL

**Status:** Accepted · 2026-09-25

## Decision

1. **Prisma 7** (`prisma-client` generator, CommonJS output compiled with
   the API, `@prisma/adapter-pg` driver adapter). Configuration lives in
   `prisma.config.ts`; the schema holds no connection URL.
2. **Two roles per environment:**

   | Role                                                    | Used by                          | Connection           | Can                                                             |
   | ------------------------------------------------------- | -------------------------------- | -------------------- | --------------------------------------------------------------- |
   | owner (`contacts_owner` on Neon, `postgres` locally/CI) | migrations only (`DIRECT_URL`)   | direct host          | everything                                                      |
   | `contact_sphere_app` (LOGIN, member of `app_runtime`)   | the running API (`DATABASE_URL`) | Neon **pooled** host | read/write rows it is granted; **no DDL**, no migration history |

   `app_runtime` is a NOLOGIN group created by the first migration; each
   environment's login role and password are created outside version control
   (`scripts/create-app-login-role.mjs`, `docs/operations/database-roles.md`).

3. **Guarantees live in the database**, in hand-written migration SQL,
   because a future endpoint, script or bug can bypass application code but
   not Postgres:
   - `audit_logs` is append-only for the app (INSERT/SELECT; UPDATE, DELETE,
     TRUNCATE revoked).
   - Audit `action` must be a dotted identifier (free text is where personal
     data leaks); `metadata` must be a JSON object.
   - `users.email` must be lower-case (making the unique index
     case-insensitive) and email-shaped.
4. **Tests prove each guarantee against real Postgres as the app role**
   (`apps/api/test/db`), in CI and locally, and refuse to run against any
   non-local host.
5. **Lazy connection:** the API connects on first query, so liveness
   (`/health`) never depends on the database; `/health/ready` reports it.
6. **Encrypted connections:** in production `DATABASE_URL` must carry
   `sslmode=verify-full` (or `require`), or the API refuses to boot.
7. **UUIDv7 primary keys**, generated by Prisma: time-ordered (index
   friendly) and they reveal no row counts.

## Why

Least privilege limits the blast radius of the most likely serious bug
class (injection, a mistaken query, a compromised dependency): the running
app cannot drop tables, alter the schema, or rewrite the audit trail. The
pooled connection keeps Neon's connection count low on a free plan; DDL
needs the direct one.

## Cost

- New tables must grant themselves correctly. Default privileges give the
  app normal read/write on future tables automatically; any table needing
  less (like the audit log) must REVOKE in its own migration, and its
  guarantee test goes in `apps/api/test/db`.
- Account deletion sets `audit_logs.actor_user_id` to NULL (a foreign-key
  action that runs with owner rights). That is the only way an audit row
  changes, and it removes a link to a person rather than rewriting history.
- Jest needs `node --experimental-vm-modules` for suites that query the
  database (Prisma 7 loads its query compiler with a dynamic `import()`).
- Prisma's install scripts are approved per exact version in
  `package.json` `allowScripts`; a Prisma upgrade needs a fresh approval.
- `overrides` pin two Prisma-CLI transitive dependencies (`deepmerge-ts`,
  `mysql2`) past published advisories. Remove when Prisma ships them.

## Revisit if

Multi-user (Phase 11): add Postgres row-level security keyed on the owner as
a second line of defence behind service-layer scoping (ADR 0004).
